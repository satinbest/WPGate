## ۱. خلاصه مدیریتی

این سند فرآیند بازرسی، ریشه‌یابی و ارزیابی صحت فنی سنجه نوشتن روی دیسک که پیش‌تر در پیشخوان مدیریت WPGate نمایش داده می‌شد را گزارش می‌کند:
```text
Runtime Disk Write IOPS: 0 Bytes (Pure RAM Execution)
نرخ نوشتن روی دیسک (IOPS): ۰ بایت (اجرای کاملاً درون‌حافظه‌ای)
```

یافته‌های بازرسی نشان می‌دهد:
۱. **ناهماهنگی مفهومی واحد IOPS:** واحد سنجه IOPS (عملیات ورودی/خروجی بر ثانیه) بیانگر تعداد تراکنش‌های خواندن و نوشتن دیسک در هر ثانیه است و بیان آن با واحد بایت («۰ بایت») از نظر علمی و مهندسی سیستم‌ها نادرست است.
۲. **نبود دسترسی مستقیم PHP به شمارنده‌های کرنل:** پردازش‌های وب PHP در هاست‌های اشتراکی به شمارنده‌های سیستمی سخت‌افزار ذخیره‌سازی (مانند `/proc/diskstats`) دسترسی بدون مجوز ندارند.
۳. **تفکیک دیتابیس از دیسک:** هرچند WPGate هیچ فایل لاگی روی فایل‌سیستم سرور ذخیره نمی‌کند، اما لاگ‌ها در جدول `wp_options` دیتابیس MySQL نوشته می‌شوند که پایگاه‌داده خود ممکن است تغییرات را روی دیسک فلاش نماید؛ بنابراین ادعای «اجرای کاملاً درون‌حافظه‌ای» برای دیتابیس دقیق نبوده است.
۴. **اصلاح مهندسی:** این سنجه جهت انطباق ۱۰۰٪ با واقعیت عملکرد نرم‌افزار به این شکل بازنویسی شد: **فایل‌نویسی روی دیسک: غیرفعال (بدون فایل روی دیسک)** همراه با توضیحات تکمیلی در تول‌تیپ.

## ۲. ریشه‌یابی سورس‌کد و جریان داده

### ۲.۱ تحلیل کامپوننت‌های فرانت‌اند
- **کامپوننت‌های رندرکننده این سنجه:**
  - `admin-ui/src/components/TabOverview.vue` (بخش اطلاعات سریع استقرار)
  - `admin-ui/src/components/TabTools.vue` (بخش مشخصات محیط سرور)
- **منشأ داده‌ها:**
  - مقدار به‌صورت ایستا از فایل دیکشنری زبان (`i18n.js`) با کلیدهای `tools.diskWrites` و `tools.diskWritesVal` واکشی می‌شد.
  - در کامپوننت `TabTools.vue` عبارت `'0 Writes (Pure Memory)'` نیز به‌صورت هاردکدشده در قالب وجود داشت.

### ۲.۲ تحلیل اندپوینت‌های REST API و بک‌اند
- بررسی توابع `RestController::get_settings()` و `RestController::get_stats()` نشان داد که هیچ متغیر یا سنجه‌ای تحت عنوان IOPS از سمت سرور محاسبه یا ارسال نمی‌شده است و این مقدار صرفاً یک برچسب ایستا در رابط کاربری بوده است.

### ۲.۳ تحلیل معماری ذخیره‌سازی (`Logger.php`)
- در کلاس `WPGate\Core\Logger` لاگ‌ها از طریق دستور وردپرسی زیر ذخیره می‌شوند:
  ```php
  update_option( self::LOG_KEY, $logs, false );
  ```
- آرگومان `false` مانع از لود خودکار (Autoload) این داده‌ها در صفحات عمومی سایت می‌شود.
- **نتیجه واقعی:** WPGate به هیچ عنوان فایلی روی دیسک ذخیره نمی‌کند (مانند پوشه `uploads` یا فایل‌های `.log`) و کلیه داده‌ها درون دیتابیس وردپرس نگهداری می‌شوند.

## ۳. جدول ارزیابی صحت فنی ادعاها

| عبارت ادعاشده قبلی | واقعیت فنی سیستم | ارزیابی کارشناسی |
| :--- | :--- | :--- |
| **"IOPS: 0 بایت"** | واحد IOPS نرخ عملیات در ثانیه است نه بایت. | **واحد نادرست** |
| **"اجرای کاملاً درون‌حافظه‌ای"** | تابع `update_option` با پایگاه‌داده رابطه دارد که روی دیسک سرور پایدار می‌شود. | **ادعای غیردقیق** |
| **"عدم تولید فایل لاگ روی دیسک"** | WPGate هیچ فایل متنی روی فایل‌سیستم سرور تولید نمی‌کند. | **حقیقت فنی معتبر** |
| **"سنسور نرخ دیسک در PHP"** | اسکریپت PHP امکان پایش سنسورهای سخت‌افزاری هاست را ندارد. | **غیرقابل سنجش در PHP** |

## ۴. اقدامات اصلاحی اعمال‌شده

۱. **اصلاح عنوان سنجه:**
   - عنوان قبلی: `نرخ نوشتن روی دیسک (IOPS)` / `Runtime Disk Write IOPS`
   - **عنوان اصلاح‌شده استاندارد:** `فایل‌نویسی روی دیسک` / `Disk File Logging`
۲. **اصلاح مقدار سنجه:**
   - مقدار قبلی: `۰ بایت (اجرای کاملاً درون‌حافظه‌ای)` / `0 Bytes (Pure RAM Execution)`
   - **مقدار اصلاح‌شده استاندارد:** `غیرفعال (بدون فایل روی دیسک)` / `Disabled (0 Files on Disk)`
۳. **تول‌تیپ توضیحی شفاف (`tools.diskWritesHint`):**
   - **فارسی:** `"وقایع در دیتابیس وردپرس ذخیره می‌شوند؛ فایل‌نویسی روی دیسک غیرفعال است و IOPS سخت‌افزاری توسط PHP اندازه‌گیری نمی‌شود."`
   - **انگلیسی:** `"Logs reside in database options; disk file logging is disabled and hardware IOPS is unmeasured."`
۴. **حذف متن‌های هاردکدشده:**
   - حذف عبارت `'0 Writes (Pure Memory)'` در `TabTools.vue` و اتصال آن به ویژگی‌های ترجمه‌شده متمرکز.

## ۵. محدودیت‌ها و نتیجه‌گیری پایانی
